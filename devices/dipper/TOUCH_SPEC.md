# Xiaomi Mi 8 (dipper) - Touchscreen Hardware & Driver Specification

Данные сняты напрямую с реального устройства Xiaomi Mi 8 (`dipper`) под управлением MIUI (`V12.0.3.0.QEAMIXM`, Android 10, ядро 4.9.x) через root и Device Tree (`/sys/firmware/fdt`).

---

## 1. Контроллер тачскрина

- **Модель чипа:** STMicroelectronics FingerTipS (FTS521 / `st,fts`)
- **Определенный тип панели:** Vendor ID `72` (`0x48`, `'H'`), тип панели `fts+sdc` (Samsung Display Super AMOLED)
- **Версия драйвера Linux:** `5.2.4` (`CONFIG_TOUCHSCREEN_ST_FTS_V521=y`)
- **Версия прошивки (из dmesg):**
  - FW VER: `0054`
  - SVN REV: `1939`
  - CONFIG VER: `0024`
  - CONFIG PROJECT ID: `0000`
  - CX VER: `FFFF`
  - AFE VER: `CFG = 02 - CX = 02 - PANEL = 02`
  - Имя прошивки в DT: `st_fts_e1.ftb`
  - Лимиты калибровки: `stm_fts_production_limits.csv`
- **Альтернативный чип (в DT также описан как fallback):** Atmel maXTouch (`atmel,mxt-ts`, `mXT640U`, I2C адрес `0x4a`). На данном экземпляре установлен именно **STMicroelectronics FTS521**.

---

## 2. Шина I2C (Qualcomm QUPv3 GENI)

- **I2C контроллер:** `a98000.i2c` (Serial Engine 14, QUPv3 wrapper 1, SE 6)
- **I2C Base MMIO:** `0x00a98000`, размер `0x4000` (16 КБ)
- **I2C 7-bit адрес тача:** `0x49`
- **Прерывание I2C контроллера (GIC):** SPI `0x167` (359)
- **Clocks (GCC - Global Clock Controller):**
  - Базовый адрес GCC: `0x00100000`
  - `se-clk` (корень): `0x18738` (ветка `0x18734`)
  - `m-ahb` / `s-ahb`: голосующий регистр `0x5200c` (биты 20, 21 для AHB, бит 28 для SE14)
- **Пины шины (GPIO):**
  - **SDA:** `GPIO 33` (функция 2: `qup14`)
  - **SCL:** `GPIO 34` (функция 2: `qup14`)

---

## 3. Линии управления (TLMM GPIO)

- **Базовый адрес TLMM:** `0x03400000`, размер `0x00c00000` (12 МБ)
  - На SDM845 пины 31–34 находятся в **Северной плитке (North Tile)** со смещением `+0x00500000` (или стандартный pinctrl-v2).
- **Прерывание тачскрина (INT):**
  - **GPIO 31**
  - Тип: `0x2008` (Active Low / Falling Edge)
  - Подтяжка в DTS: `bias-pull-up`, `drive-strength = 16 mA` (`0x10`)
  - Поведение: линия опускается в LOW, пока у чипа есть непрочитанные события в FIFO.
- **Сброс тачскрина (RESET):**
  - **GPIO 32**
  - Полярность: Active Low (0 = сброс, 1 = рабочее состояние)
  - Подтяжка в DTS: `bias-pull-up`, `drive-strength = 16 mA` (`0x10`)
  - **Критичные задержки сброса:**
    1. Удерживать RESET = 0 не менее 20 мс (`msleep(20)`).
    2. Поднять RESET = 1.
    3. Ждать выхода из сброса и внутренней калибровки сенсора **не менее 60–100 мс** перед первым обращением по I2C!

## 4. Питание (Regulators)

- **Цифровое питание шины / VDDIO (`vdd-supply`, phandle 0x96):**
  - Регулятор `disp_vddio_vreg` (1.8 V)
  - Управляется через **GPIO 23** (`enable-active-high`), задержка запуска `4000` мкс (4 мс).
  - В DT помечен `regulator-boot-on`.
- **Аналоговое питание матрицы / AVDD (`avdd-supply`, phandle 0x97):**
  - Регулятор `pm8998_l28` (3.3 V, `0x325aa0` мкВ)
  - Управляется через RPMh VRM (`ldoa28`).
  - В DT помечен `regulator-boot-on`.

## 5. Протокол STMicroelectronics FTS (v5.2.1)

- **Команды I2C:**
  - `0x80` — Read Chip / Info
  - `0x85` — Read One Event (чтение 8 байт из стека событий)
  - `0x91` — Sleep Out / Wake up
  - `0x92` — Sleep In
  - `0x93` — Sense On (включение мультитача)
  - `0xa1` — Clear Event Stack (очистка очереди прерываний)
- **Формат события (8 байт на событие при чтении 0x85):**
  - Байт 0: `[7:4]` = ID пальца (0–9), `[3:0]` = тип события:
    - `0x03` = Contact Down (касание)
    - `0x04` = Contact Up / Leave (отрыв)
    - `0x05` = Contact Move (движение)
  - Байт 1: Младшие 8 бит X (`x[7:0]`)
  - Байт 2: `[3:0]` = старшие 4 бита X (`x[11:8]`), `[7:4]` = младшие 4 бита Y (`y[3:0]`)
  - Байт 3: Старшие 8 бит Y (`y[11:4]`)
  - Разрешение панели: `1080 x 2248`
- **Квитирование:** пока FIFO не пустое, чип удерживает GPIO 31 в нуле. При чтении всех событий FIFO опустошается, и GPIO 31 возвращается в 1.

## 6. Причины краша ядра XNU и правила безопасного портирования

1. **MMIO Bus Fault при выключенных клоках:**
   - Если ядро читает/пишет `0x00a98000` (QUPv3 SE14) до того, как GCC/RPMh подал тактирование и питание на шину, процессор ARM64 ловит аппаратный `Data Abort` / `SError`, что приводит к немедленному Kernel Panic.
2. **Бесконечный цикл ожидания GENI (Watchdog Timeout):**
   - Если I2C слейв не ответил (NACK), микроконтроллер QUP GENI зависает в статусе ожидания. Чтение без таймаута подвешивает ядро. Обязательны таймауты и посылка `M_GENI_CMD_CANCEL` / `M_GENI_CMD_ABORT`.
3. **Безопасный опрос (Safe Probe):**
   - Драйвер не должен завершать поток или паниковать при неудаче `i2c_read`. При отсутствии ответа драйвер должен выдать сообщение в dmesg и корректно уснуть.
